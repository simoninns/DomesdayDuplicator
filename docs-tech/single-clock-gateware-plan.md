# Single-clock gateware implementation plan

Plan for restructuring the FPGA gateware from two clock domains joined by a
proprietary dual-clock FIFO into a single clock domain with a locally
implemented FIFO and a clock-enable-decimated sampling path.

- Status: phase 1 implemented; phases 2 to 6 outstanding
- Scope: `fpga/` only. No FX3 firmware change expected; docs and tests updated
  alongside. The external contracts (GPIF protocol, SPI register map, sample
  data format) are unchanged.

## 1. Why this is achievable and correct

### 1.1 The current structure

The gateware today has two clock domains, both generated by `IPpllGenerator`
(altpll) from the DE0-Nano's 50 MHz oscillator:

| Clock | Rate | Drives |
| --- | --- | --- |
| `adc_clock` (PLL c1) | 40 MHz | ADS825 ADC clock pin, `dataGenerator`, FIFO write side |
| `fx3_clock` (PLL c0) | 60 MHz | FX3 GPIF `PCLK` output, FIFO read side, `fx3StateMachine`, `spiRegisters` |

The domains meet in `buffer.v`: a ping-pong pair of 8192 × 16 `dcfifo`
instances (`IPfifo`, Altera proprietary IP). The write side fills one buffer
while the FX3 drains the other; `data_available` is raised when the read-side
buffer is full, and the FX3 then reads exactly 8192 words (one 16 KiB USB
endpoint buffer) at 60 MHz. Because the drain rate (60 Mwords/s) exceeds the
fill rate (40 Mwords/s), the FX3 catches up after USB3 stalls.

### 1.2 The FX3 does not require a second domain

The GPIF II interface is a **synchronous slave clocked externally by the
FPGA** — the FPGA drives `PCLK` (FX3 GPIO_16, from `GPIO1[31]`). The FX3 side
adapts to whatever `PCLK` it is given, up to the GPIF II limit of **100 MHz**
for a 16-bit synchronous interface. The FX3 firmware nowhere encodes
60 MHz: `pibClock` is the internal PIB block clock (100.8 MHz, must merely be
≥ the interface clock), the GPIF descriptor is frequency-agnostic, and the DMA
watermark maths in `domesday-duplicator.c` is in words, not nanoseconds. So the
FPGA is free to pick a different `PCLK`, and **no FX3 firmware change is
needed**.

### 1.3 The clock must be an integer multiple of 40 MHz

One constraint sharpens the "single clock faster than 40 MSPS" idea: the
ADS825 needs a **uniform** 40 MHz clock — it is the ADC clock edge that defines
the sampling instant, so any period-to-period non-uniformity is sampling
jitter, which directly degrades the captured RF. A uniform 40 MHz clock can
only be derived from a single master clock by integer division. That rules out
keeping 60 MHz (60/40 = 1.5) and gives two candidates:

- **80 MHz** — ADC clock = ÷2 (exactly 50 % duty, trivially). GPIF at 80 MHz,
  within the 100 MHz limit. **Chosen.**
- 120 MHz — GPIF cannot be clocked above 100 MHz, so `PCLK` would have to be a
  ÷2 (60 MHz) fabric-divided output with the GPIF logic on a clock enable, and
  the ADC clock a ÷3, which cannot reach 50 % duty from one clock edge (the
  ADS825 wants ≥ ~11 ns in each phase at 40 MSPS, and 33/67 duty violates
  that). More logic, harder timing closure, no benefit. Kept only as a
  fallback (§6) because it preserves today's validated 60 MHz FX3 link.

At 80 MHz everything runs in one domain:

- The ADC clock pin is driven by a registered divide-by-2 toggle flip-flop
  (placed in the I/O register). Because the same flip-flop *is* the phase
  reference, the fabric knows by construction which 80 MHz cycle corresponds
  to the ADC clock rising edge — no alignment or synchronisation step needed.
- The sampling path (`dataGenerator`) runs on the 80 MHz clock with a clock
  enable asserted every second cycle, phased so ADC data is captured at the
  same point in the ADC clock cycle as today (the current design captures on
  the following 40 MHz rising edge, i.e. one full period after launch, well
  inside the ADS825's output delay/hold window).
- The FIFO, `fx3StateMachine` and `spiRegisters` run full-rate at 80 MHz.
  `spiRegisters` already treats all SPI inputs as asynchronous (two-flop
  synchronisers plus glitch filters), so it is clock-rate agnostic — the
   2 MHz SPI ceiling derivation in the docs actually gains margin.

The catch-up property is preserved and improved: drain 80 Mwords/s vs fill
40 Mwords/s gives 2× headroom (today: 1.5×).

### 1.4 Correctness improvements that fall out for free

- **Latent CDC bug removed.** `buffer.v` reads `current_write_buffer` (written
  on the 40 MHz domain) directly in the 60 MHz read-side process with no
  synchroniser. It works in practice because the flag toggles rarely, but it
  is a real clock-domain-crossing violation. Single clock eliminates the whole
  class.
- **Exact occupancy.** Today the read side sees the write-side word count
  through the dcfifo's 5-stage sync pipes, so `data_available` decisions are
  made on stale counts. With one clock the count is exact, so the
  ≥ 8192-words-available threshold guarantees the FX3 read of exactly 8192
  words can never underflow — provable, not just observed.
- **`buffer.v` becomes simulable.** `run-sim.sh` documents that `buffer.v` is
  untested because `dcfifo`/`altpll` need Altera's `altera_mf` simulation
  library. A local FIFO in plain Verilog brings the entire data path under the
  existing Icarus testbench suite.
- **Proprietary FIFO IP gone.** `IPfifo.v`/`IPfifo_bb.v`/`IPfifo.qip` are
  deleted; only the PLL remains as generated IP (unavoidable — it's a hardware
  primitive).

### 1.5 The RAM claim, honestly

The dual-clock FIFO primitive itself does not cost double the RAM — a
`dcfifo` and a single-clock FIFO of the same depth use the same M9K bits. What
doubles the RAM today is the **ping-pong pair**: 2 × 8192 × 16 = 256 Kbit of
the EP4CE22's 594 Kbit.

The single-clock design replaces the pair with **one** FIFO whose
`data_available` is a simple occupancy threshold (≥ 8192 words). Depth then
becomes a free parameter that trades RAM for USB-stall tolerance:

| Depth | RAM | Stall grace after `data_available` |
| --- | --- | --- |
| 16384 (recommended) | 256 Kbit (same as today) | 8192 words ≈ 205 µs (same as today) |
| 8192 + margin | ~130 Kbit (half) | ~0 — any FX3 response delay overflows |

Recommendation: **keep 16384 words**. The stall tolerance is a product
property worth preserving, there is no RAM pressure on the EP4CE22, and the
depth is a one-line parameter if that changes. The simplification win is
real either way: one FIFO, no ping-pong steering, no async-clear machinery.

Overflow semantics improve too: today an overflow *async-clears an entire
8192-word buffer* (destroying already-captured samples). The new FIFO simply
drops incoming samples while full and asserts `buffer_error`; the sequence
numbers stamped in `dataGenerator` still let the host see the gap, and less
data is lost per event.

## 2. Target architecture

```
50 MHz osc ──► PLL ──► 80 MHz clk_sys ──┬─► ÷2 toggle FF ──► ADC clock pin (40 MHz)
                                        │        │
                                        │        └── phase = clock enable "sample_enable"
                                        │
                                        ├─► dataGenerator   (80 MHz, CE = sample_enable)
                                        ├─► fifo (new)      (80 MHz, 16384 × 16, FWFT)
                                        ├─► fx3StateMachine (80 MHz)
                                        ├─► spiRegisters    (80 MHz)
                                        └─► PCLK pin to FX3 (80 MHz)
```

Module changes:

| File | Change |
| --- | --- |
| `IPpllGenerator.v` | Regenerate: single output c0 = 80 MHz (50 × 8/5). c1 removed. |
| `IPfifo.v`, `IPfifo_bb.v`, `IPfifo.qip` | Deleted; `.qsf`/`.qip` references removed. |
| `fifo.v` (new) | Single-clock FIFO, 16384 × 16, inferred simple dual-port RAM, first-word-fall-through (show-ahead, matching what the GPIF path relies on today), `used` count, `full`, `empty`. Parameterised depth/width. |
| `buffer.v` | Rewritten around one `fifo` instance: `data_available <= (used >= 8192)` (registered), write gated off when full + `buffer_error` pulse-stretch (keep the ~1000-cycle hold so the FX3/host can observe it). Ping-pong, async-clear and dual-clock logic all deleted. |
| `dataGenerator.v` | Gains `sample_enable` input; ADC capture, test pattern and sequence counter advance only when enabled. Logic otherwise unchanged. |
| `fx3StateMachine.v` | Unchanged logically (clock renamed). Opportunity: convert `word_counter` blocking assignments to non-blocking while touching it. |
| `spiRegisters.v` | Unchanged (already async-safe). |
| `DomesdayDuplicator.v` | One clock net; ADC clock divider FF; wire `sample_enable`; `PCLK` pin driven from the 80 MHz clock as today (same mirror-the-clock structure, new rate). |
| `DomesdayDuplicator.SDC` | Real constraints (see §4). |

Reset: `fx3_reset_n` is asynchronous from the FX3. Keep the existing
async-assert style but add a two-flop deassert synchroniser onto the 80 MHz
domain in the top level, and use the synchronised reset fabric-wide — with one
domain there is now exactly one reset story.

## 3. Implementation phases

Each phase leaves the tree building (`run-lint.sh`, `run-style.sh`,
`run-format.sh`, `run-sim.sh`) and is a natural commit boundary.

### Phase 1 — local FIFO with testbench (no integration yet) — **done**

Delivered as `fpga/src/fifo.v` and `fpga/tests/tb_fifo.v`. Nothing instantiates
the FIFO yet, so the bitstream is unchanged; `.qsf` registration moves to
phase 2 with the `buffer.v` rewrite that uses it.

What the module does, where it differs from the sketch above:

- Parameterised on `DataWidth` and `Depth`, storage inferred rather than IP:
  the memory array and its output register sit in an always block with **no
  reset**, because a reset on that block denies Quartus the M9K inference and
  spends 262144 logic-element bits instead. The pointers and occupancy count
  keep the design's usual async reset in a block of their own.
- **A write-to-read bypass was needed and is not optional.** With show-ahead
  the FIFO reads one address ahead, so a word written into an empty queue is
  being read on the same edge it is written, and Quartus does not promise
  read-during-write behaviour for an inferred simple dual-port memory. Without
  the bypass that word is undefined — which is the case that occurs whenever
  the FX3 is keeping up completely.
- **Depth need not be a power of two.** The pointers wrap on a compare against
  the last address rather than by letting a counter overflow. That costs one
  comparator each and makes the depth-versus-stall-tolerance trade in §1.5 a
  safe edit rather than a silent corruption.

Verification:

- All four gates pass (`run-lint.sh`, `run-style.sh`, `run-format.sh`,
  `run-sim.sh`), and the three FPGA `nix flake check` derivations build.
- The testbench runs the full sequence at three depths — 6 (not a power of
  two), 8, and 16384 (the instrument's) — in about one second.
- Held up by mutation testing rather than by passing: nine mutations of
  `fifo.v` (bypass removed, look-ahead removed, either pointer wrapping by
  overflow, writes accepted while full, reads accepted while empty, occupancy
  miscounted on a simultaneous read and write, `full` off by one, bypass
  firing on every write) were each confirmed to make the testbench fail. The
  two overflow-wrap mutations are caught **only** by the depth-6 case, which is
  why it is there.

Still to confirm, and it needs Quartus, so it belongs to phase 3: that the
memory infers as M9K rather than logic. Check the fitter report for 32 M9K
blocks and no unexpected LE count.

### Phase 2 — rewrite `buffer.v` on top of it

1. Replace ping-pong logic with one FIFO + threshold `data_available` +
   write-gating overflow behaviour with the held `buffer_error` flag. Add
   `VERILOG_FILE fifo.v` to `DomesdayDuplicator.qsf` in the same change —
   phase 1 deliberately left it out, because a source file the project lists
   but nothing instantiates is dead weight for a phase.
2. Write `tests/tb_buffer.v` — newly possible without `altera_mf`. Cover:
   steady-state 2-writes-per-5-reads cadence (40 vs 80 MHz emulated via the
   enable), an exact 8192-word packet drain per `data_available`, a stalled
   reader driving overflow and recovery, `buffer_error` hold duration,
   behaviour across reset.
3. Update the "buffer.v is untested" commentary in `run-sim.sh` and
   `fpga/README.md`.

### Phase 3 — single-clock top level

1. Regenerate `IPpllGenerator` for one 80 MHz output (Quartus MegaWizard;
   update `.ppf`/`.qip` alongside, note generator version in the commit).
2. Top level: add the ÷2 ADC-clock toggle FF (with an I/O output register
   assignment in the `.qsf` so the pin timing is register-determined), derive
   `sample_enable` from it, and phase the capture enable to match today's
   capture point (capture on the 80 MHz edge coincident with the ADC clock
   rising edge, i.e. one full ADC period after launch).
3. Thread `sample_enable` into `dataGenerator`; update `tb_dataGenerator.v`
   to drive clock+enable and assert the sequence/test patterns advance at the
   decimated rate.
4. Add the reset synchroniser; clock `fx3StateMachine`/`spiRegisters`/
   `buffer` from `clk_sys`.

### Phase 4 — timing constraints (the real ones)

Replace the two-line SDC with:

1. `create_clock` 50 MHz input; `derive_pll_clocks`.
2. `create_generated_clock` on the ADC clock output pin (÷2 of the PLL clock,
   from the divider FF).
3. `create_generated_clock` on the `PCLK` pin (mirror of the 80 MHz clock).
4. `set_input_delay` on `adc_databus[9:0]` vs the ADC generated clock, from
   the ADS825 datasheet (output delay/hold), plus a multicycle exception
   matching the ÷2 enable cadence.
5. `set_output_delay` on the FX3 databus, `dataAvailable`, `bufferError` vs
   the `PCLK` generated clock, from FX3 sync-slave setup/hold (tS = 2 ns,
   tH = 0.5 ns); `set_input_delay` on `readData` (FX3 CTL output delay).
6. SPI and LED pins false-pathed (async, already synchronised in fabric).

Gate: Quartus timing analysis clean at 80 MHz on all constrained paths. The
FX3 input path (`readData` arrives ~7.5 ns after the `PCLK` edge, leaving
~5 ns before the next 80 MHz edge) is the tightest — it is expected to close
(the design already re-registers `readData` and the GPIF protocol tolerates
the extra cycle), but if it does not, capture it on the falling edge or adjust
`PCLK` phase in the PLL, both purely FPGA-side fixes.

### Phase 5 — cleanup and documentation

1. Delete `IPfifo*` files; purge from `.qsf`, `.cof`, lint scripts.
2. Update `fpga/README.md` (module table, sim coverage note).
3. Update `docs/content/development/hardware-guide.md` (dual-clock FIFO
   paragraphs → single-clock description) and
   `fpga-register-interface.md` (the "60 MHz" references in the SPI ceiling
   derivation become 80 MHz; ceiling unchanged or looser).
4. Check `verible-waivers`/`verilator-waivers.vlt` for entries tied to
   deleted files.

### Phase 6 — hardware validation

1. Build with `build-local.sh`, program a DE0-Nano.
2. SPI sanity: GUI reads gateware version/commit registers (proves 80 MHz
   `spiRegisters` + SPI path).
3. Capture-integrity procedure from `TESTING.md` §5 in test mode: the
   incrementing test pattern plus sequence numbers verify, end-to-end, that
   no sample is dropped, duplicated or reordered at full rate — this is the
   decisive test for both the new FIFO and the 80 MHz GPIF link.
4. Long-duration test-mode capture (≥ 30 min) to shake out rare timing
   marginality; then real ADC capture and spectrum eyeball against a
   pre-change capture to confirm no analogue regression (the ADC clock source
   changes from PLL output to fabric FF; jitter contribution is expected to be
   negligible at 40 MSPS but should be confirmed by looking at the noise
   floor).
5. Deliberate stall test: pause the host reader briefly mid-capture and
   confirm `bufferError` reporting and sequence-number gap behave as
   documented.

## 4. Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| FX3 GPIF link marginal at 80 MHz over the DDD board interconnect | Low (spec'd to 100 MHz; short traces) | Constrain and measure first (Phase 4); PLL phase-shift `PCLK` if needed; fallback: 120 MHz fabric with ÷2 `PCLK` = 60 MHz + GPIF clock enable, keeping today's validated link rate (costs a negedge FF for the 50 %-duty ÷3 ADC clock) |
| ADC capture timing regression | Low | Same capture instant as today by construction; explicit input constraints make it visible to the fitter, which the current design never had |
| ADC clock quality from fabric FF vs PLL output | Low | I/O register output, 50 % duty exact; validate noise floor in Phase 6 |
| Hidden 60 MHz assumption in FX3 firmware or GUI | Very low | Reviewed: PIB clock, GPIF descriptor and watermark logic are all frequency-agnostic; Phase 6 exercises the full stack |

## 5. Explicitly out of scope

- FX3 firmware changes (none required; the GPIF descriptor, DMA layout and
  register protocol are untouched).
- Sample rate or data format changes — still 40 MSPS, 10-bit samples in
  16-bit words with 6-bit sequence numbers, 8192-word packets.
- The legacy `gui/` (per project decision, only `ddd-gui` matters).
- Raising the sample rate. Worth noting for the future: with the fabric at
  80 MHz and a parameterised divider, other rates that divide 80 evenly
  (e.g. 20, 40 MSPS) become a small change, but that is not part of this work.
